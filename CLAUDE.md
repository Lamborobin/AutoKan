# Entry point

> **Before starting any task, read every context file marked `Read` in the table below (always `docs/rules.md`).** Files marked `On demand` should be loaded only when the row's "Read when…" condition matches the task you're working on.

> **CLAUDE.md is the master delegator.** Files inside `docs/` must not reference, link to, or mention each other — cross-references create loops and obscure the dependency hierarchy. Every agent starts here, then jumps directly to the file it needs from the tables below. Only `CLAUDE.md` and `README.md` are allowed to index docs files.

> **App code and UI text should not name specific `docs/*.md` files either.** Describe the *category* of content ("AI-level rules", "architectural reference", "decisions log") instead of listing filenames. Hardcoded paths to docs files create rename-coupling: a future restructure has to chase them down across the codebase. The only legitimate places that name docs files are `CLAUDE.md` (this index), `README.md`, and `server/src/config/agent.config.json`'s `ai_context.groups` (the AI Context panel's source of truth).

> **Do not edit this file** unless adding a new context file or updating the tables below. All other content belongs in `docs/`.

## Context Files
| File | Load | Read when… |
|---|---|---|
| `docs/rules.md` | Read | Hard constraints that apply to every task — cannot be bypassed |
| `docs/agents.md` | On demand | Agent logic, flows, behavior prompts, instruction file system, escalation behavior |
| `server/src/seed/runners.json` | On demand | Capability definitions and (capability, column) → runner mappings. Single source of truth for what each agent skill is and which flow fires in which column. |
| `docs/frontend.md` | On demand | Any file under `app/src/` |
| `docs/api.md` | On demand | Implementing, modifying, or calling API routes |
| `docs/architecture.md` | On demand | Architectural design choices, structural decisions, system design |
| `docs/decisions.md` | On demand | Before reversing or changing a significant design decision |
| `docs/upcoming-changes.md` | On demand | Before starting work that might overlap with planned features |

## When to update each file
| File | Update when |
|---|---|
| `CLAUDE.md` | A new context file is added to `docs/`, or this index needs to change |
| `README.md` | Tech stack, quick start steps, quick information about architecture & use case |
| `docs/rules.md` | A new hard constraint is agreed on |
| `docs/agents.md` | Agent behavior, flows, or the instruction file system changes |
| `server/src/seed/runners.json` | A capability is added/renamed, or a runner is added/changed/wired up |
| `docs/frontend.md` | A new component pattern, threshold, or store structure is established |
| `docs/api.md` | An API route is added, removed, or its behavior changes |
| `docs/architecture.md` | A structural or system design decision is made |
| `docs/decisions.md` | A significant design decision is made or reversed |
| `docs/upcoming-changes.md` | A feature is planned, agreed on, or completed |

**What is this project**: Autonomous AI agent task orchestration system — a kanban board where AI agents (PM, Developer, Tester) work through tasks autonomously with or without human involvement.

**Purpose**: This tool manages the full lifecycle of a client's project through a kanban board operated by AI agents and humans together.
